# 백지 (Blank Page) — 인출이 저장을 만든다

재읽기는 저장을 만들지 않는다. 각인시킬 지식을 오늘 등록하면
**오늘 · 3일 · 10일 · 30일 · 90일, 딱 5회** 일정이 자동으로 잡히고,
그 날짜에 알림이 온다. 방법은 하나 — **빈 종이에 손으로 재현한다.**
다 쓴 뒤 앱에 옮겨 적거나 종이를 찍어 올리면, 폰의 claude 가 원본과 대조해
무엇이 맞았고 무엇이 빠졌고 무엇이 틀렸는지 짚어준다.
**원본은 제출하기 전까지 열리지 않는다.** 보고 그리는 건 연습이 아니기 때문이다.

## 화면

| 탭 | 하는 일 |
|---|---|
| **오늘** | 오늘 인출할 것만. 카드에는 제목만 보인다 — 제목이 유일한 단서다. 알림을 탭하면 여기를 건너뛰고 재현 화면으로 바로 간다 |
| **달력** | 한 달 스케줄표. 셀의 점 색이 상태(예정·완료·놓침), 점 크기·명도가 회차. 날짜를 누르면 아래에 그 날 목록이 뜬다 |
| **서재** | 등록한 지식 전체와 5회차 진행 점. 예정된 회차가 남아 있는 동안 원본은 잠겨 있다 |

## 5회 규칙

| 회차 | 시점 | 통과 시 | 실패(무너짐) 시 |
|---|---|---|---|
| 1 | 등록 직후 (D0) | 다음은 D+3 | **다음 날 재시도**를 끼워 넣는다 |
| 2 | D+3 | 다음은 D+10 | 〃 |
| 3 | D+10 | 다음은 D+30 | 〃 |
| 4 | D+30 | 다음은 D+90 | 〃 |
| 5 | D+90 | **졸업 · 아카이브** | 〃 |

- **부분재현(amber)** 은 통과시키되 다음 회차만 30% 당긴다. 겨우 버틴 기억을 원래 간격으로 밀면 다음에 무너진다.
- **무너짐(red)** 에 전체 리셋은 하지 않는다. 이미 굳은 다른 부분까지 벌하면 사람이 지친다. 다음 날 한 번 더 하고, 통과하면 원래 캘린더로 복귀한다.
- 놓친 회차는 **사라지지 않고 이월**된다. 하루 상한(기본 7개)을 넘으면 접어서 보여줄 뿐이다.
- 동시에 살아 있는 항목은 기본 30개까지. 넘으면 신규 등록이 막힌다 — 이 앱이 플래시카드 더미로 퇴화하는 걸 막는 장치다.

## 채점

앱은 LLM을 직접 호출하지 않는다. **폰의 Termux 에 이미 로그인된 claude CLI** 가 전부 처리한다(추가 비용 없음).

1. **등록 시 1회 정규화** — 원본을 "따로 기억해낼 수 있는 최소 단위" 요소표로 쪼갠다. 요소 id 가 고정돼야 5회차를 가로질러 "3일차엔 맞았는데 30일차엔 빠졌다"를 추적할 수 있다. CLI 가 죽어 있어도 등록은 막히지 않는다 — 줄 단위 임시 요소표로 먼저 저장하고 나중에 갈아끼운다.
2. **제출 시 채점** — 요소마다 맞음 / 빠뜨림 / 틀림 / 순서오류 중 하나. 원본에 없는데 쓴 것은 따로 모은다. 표현이 달라도 뜻이 같으면 정답이고, 숫자는 등록 때 정한 허용오차로 본다. 프롬프트에 **후한 채점 금지**가 박혀 있다 — 스스로를 속이면 이 앱은 무의미해진다.
3. 사진으로 낸 종이는 CLI 가 `Read` 로 읽어 먼저 옮겨 적고(transcript) 그 다음 채점한다. 그래야 감점 원인이 판독 실패인지 기억 누락인지 갈린다.

프롬프트와 스키마는 `app/src/main/assets/` 에 한 벌로 있고 앱과 CLI 가 같은 파일을 읽는다.

### 브릿지 프로토콜

```
앱 → 터미널 : /sdcard/Download/blank/req_*.txt  +  Termux RUN_COMMAND (`blank run <파일>`)
터미널 → 앱 : am broadcast -n com.blank.app/.cli.CommandReceiver -a com.blank.app.CMD
              -e cmd result -e req <id> --ei part <i> --ei parts <n> -e json <조각>
```

회신을 파일로 하지 않는 이유: Android 10+ 범위 지정 저장소에서 앱은 자기가 만들지 않은 파일을 못 읽는다.
결과 JSON 은 binder 한도를 피해 조각내 보내고 앱에서 다시 붙인다.

### 터미널 쪽 준비 (한 번만)

```bash
ln -sf ~/blank-page/tools/blank ~/bin/blank
blank log        # 최근 채점 로그
blank drain      # RUN_COMMAND 가 막혀 밀린 요청 처리
blank watch      # 계속 지켜보며 처리
```

## 알림

"그 날 그 시각"이 이 앱의 본질이라 `AlarmManager.setExactAndAllowWhileIdle` 를 쓴다(WorkManager 는 Doze 에서 수십 분 밀린다).
항목마다 알람 4개를 다 걸지 않고 **가장 빠른 미완료 회차 하나만** 건다 — 진실은 DB 에 있고 알람은 포인터다.
재부팅·시간 변경·앱 업데이트에서 전부 다시 걸고, 하루 한 번 WorkManager 안전망이 훑는다.
**알림에는 제목과 회차만 넣는다.** 본문이 한 글자라도 새면 그건 힌트고, 힌트를 본 재현은 인출이 아니다.

## 기술 스택

- Kotlin + Jetpack Compose (Material3 **다크 전용**: 배경 `#121212`, 카드 `#1E1E1E`, 포인트 `#7C5CFF`, 재현 화면만 `#0A0A0B`)
- minSdk 29 / targetSdk 35 / compileSdk 35, arm64-v8a
- Room (항목·리비전·회차·제출·채점), DataStore (설정)
- 원본은 **불변 리비전**으로 쌓인다. 회차는 알림이 나가는 순간의 리비전 id 를 붙들어서, 나중에 원본을 고쳐도 과거 채점이 깨지지 않는다.

## 빌드 (GitHub Actions)

로컬(Termux)에서는 빌드하지 않는다. push 하면 Actions 가 APK를 만든다.

1. `main` 에 push → Actions → 최신 실행 → Artifacts 의 `blank-apk`
   (`blank-debug.apk`, `blank-release.apk` — 릴리즈도 debug 키로 서명돼 바로 설치된다)
2. 태그 릴리즈: `git tag v1.0.0 && git push --tags` → Releases 에 APK 자동 첨부

## 첫 실행

1. APK 설치 → 알림 권한 허용 → 설정에서 알림 시각 확인(기본 8시)
2. 터미널에서 `ln -sf ~/blank-page/tools/blank ~/bin/blank`
3. **+** 로 첫 지식 등록 → 바로 D0 인출이 뜬다

## 주의

- 릴리즈 APK는 debug 키로 서명돼 있다(개인용). 배포하려면 별도 signingConfig 을 추가할 것.
- 채점은 Termux 가 살아 있어야 돌아간다. 실패해도 재현물은 저장되고, `blank drain` 으로 나중에 채점된다.
